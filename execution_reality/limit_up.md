# حد الصعود والهبوط

## 1. الأرقام في E1_base

| العنصر | العدد |
|---|---:|
| `limit_up_1400` مستبعد | **703** |
| `close_limit_up` مستبعد | **120** |
| صفقات مختارة كانت limit-up | **0** |
| `limit_down` كفلتر بيع | **غير موجود** |
| sell limit-down test | **غير متوفر** |

## 2. كيف حُسب الحد؟

### 14:00

```text
ret_pre = p14_adj / prev_close − 1
limit_up_1400 = ret_pre >= 9.5%
```

هذا **proxy**، وليس حد بورصة رسميًا. لا توجد وثيقة EGX أو tick size.

### الإغلاق

```text
close_limit_up = ret1_D >= 9.5%
```

- يُستخدم **فلتر تنفيذ** فقط: إذا كان السهم سيغلق limit-up، لا يمكن الشراء عند الإغلاق.
- لا يُستخدم في ترتيب 14:00.
- 120 مرشحًا استُبعدوا؛ 0 مختار.

## 3. هل هذا كافٍ؟

**لا.**

- لا نعرف حد EGX الفعلي لكل سهم/سنة.
- 9.5% قد يكون قريبًا من 10% لكنه ليس دقيقًا.
- لا نعرف هل السهم كان مقفلًا (bid فقط) أم لا.
- لا نعرف حجم الطابور عند الحد.
- لا يوجد اختبار لما يحدث إذا كان البيع عند الافتتاح في سهم limit-down.
- 21 صفقة خرجت 14:00 بعد فجوة؛ قد تكون في وضع حد سفلي.

## 4. الثغرة الأهم

الباكتست **لا يمنع البيع** في سهم limit-down. إذا كان الافتتاح limit-down، فقد لا تستطيع الخروج، أو تبيع بسعر أسوأ. لا يوجد اختبار لذلك. هذا قد يزيد الخسائر في الأيام الصعبة.

## 5. المطلوب

1. حدود EGX الرسمية لكل سنة/سهم.
2. bid/ask وحجم عند الحد.
3. سجل أوامر يظهر الرفض/الجزاء.
4. اختبار sell-side limit-down.
5. اختبار partial fills.

كلها **غير متوفرة**.
